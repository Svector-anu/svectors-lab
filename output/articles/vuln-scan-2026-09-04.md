## Candidates reviewed: 58 | Confirmed: 0

### Code findings (semgrep) — 3 candidates, 0 confirmed
1. **`src/Adapters/Files/GridFSBucketAdapter.js:168`** — `gcm-no-tag-length`. `crypto.createCipheriv('aes-256-gcm', key, iv)` doesn't pass an explicit `authTagLength`, but Node's default for AES-GCM is already the secure 16-byte (128-bit) tag. Not attacker-reachable (server-side file encryption using an operator-configured key). **False positive — dropped.**
2. **`src/middlewares.js:412`** — `cors-misconfiguration`. The `allowCrossDomain` handler only ever reflects `Access-Control-Allow-Origin` back as either an operator-configured allowlisted origin (exact match against `req.headers.origin`) or the configured default — never an arbitrary attacker-supplied origin. No `Access-Control-Allow-Credentials` header is set anywhere in the codebase, so even the reflection case carries no credentialed cross-origin risk. **False positive — dropped.**
3. **`src/password.js:33`** — `detected-bcrypt-hash`. The hardcoded hash is an intentional dummy value (`dummyHash`) used to normalize `bcrypt.compare()` timing when no real password hash exists — a standard defense against user-enumeration via timing side channel, not a leaked credential. **False positive — dropped.**

Remaining 72 semgrep hits were all `github-actions-mutable-action-tag` warnings (Actions referenced by version tag instead of pinned SHA) across `.github/workflows/*.yml` — a supply-chain hardening suggestion, not an exploitable code vulnerability. Not routed to disclosure or PR this run.

### Agentic logic audit (A3.6)
Threat model: Parse Server is a backend-as-a-service exposing a REST/GraphQL API over user data; the top attacker goals are auth/ACL bypass (accessing another app's or user's data), NoSQL injection via query constraints, and information disclosure through error messages or misconfigured CORS.

Reviewed (budget N=10, 374 code files → mid-size tier): master-key/session gating in `RestQuery.js` (consistently checks `this.auth.isMaster`/`isMaintenance` before privileged paths), the CORS trust boundary in `middlewares.js` (see above), password hashing (`password.js`), and GraphQL schema-disclosure hardening in `ParseGraphQLServer.js` (already redacts type identifiers from validation error messages unless the caller referenced them in their own operation text — a deliberate, already-fixed information-disclosure guard).
