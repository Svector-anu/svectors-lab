## Triage — 7 semgrep candidates → 1 confirmed

- **`use-defused-xml` — `audit_website.py:72` → CONFIRMED (medium).** Raw
  `xml.etree.ElementTree.fromstring` on a remote, attacker-controlled sitemap.
  etree is safe from external-entity XXE (pyexpat, since 3.7.1) but expands
  *internal* DTD entities, so a hostile sitemap of a few hundred bytes inflates
  to gigabytes in memory → host DoS. The 4 MB fetch cap is on input bytes and
  does nothing against post-parse expansion. Verified locally: 388 B → 3 MB
  (~7,700×) at just 7 entity levels; more levels go exponential. Reachable from
  the tool's core use case (`audit_website.py --base/--sitemap <untrusted site>`)
  via `collect_urls → _recurse → fetch → parse_sitemap`.
- **`run-shell-injection` ×2 — `.github/workflows/release-images.yml:28,63` →
  dropped.** `${{ github.ref_name }}` interpolated into a `run:` step, but the
  workflow only fires on `push: tags: v*` / `workflow_dispatch`; the tag name is
  set by someone who already has push access, so the injection yields nothing
  beyond what the pusher already holds. Defense-in-depth hardening at most.
- **`dangerous-subprocess-use-tainted-env-args` ×3 — `image_meta.py:371,468,546`
  → dropped.** All are list-form `subprocess.run` (no `shell=True`); the
  "tainted" input is an upstream-model *directory* read from an env var and
  validated with `.is_dir()`. No shell, no command injection.
- **`httpsconnection-detected` (WARNING) — `audit_website.py:268` → dropped.**
  Informational; the connection code pins validated public IPs and enforces
  TLS ≥ 1.2.

**Not a duplicate:** PR #49 hardened this same file against SSRF and gzip bombs
but did not guard XML entity expansion on the parser those bytes flow into. No
open/closed issue or PR mentions the sitemap XML parser, entities, billion-laughs,
or defusedxml.

## Dependency scan (osv) — noted, not filed

osv-scanner reported 264 vulnerable-package rows, but **all** are pinned versions
inside the optional ML-harness requirements files
(`service/scripts/requirements-{synthid,markllm,ctrlregen,markdiffusion}*.txt` —
torch/transformers/diffusers/aiohttp/pillow/pip/setuptools). These are heavy,
opt-in backends that run in dedicated Docker images, not core-tool dependencies,
and the repo already runs Dependabot (several bump PRs open: #61, #63, #66). No
dependency PR filed (and repo fork returns 403 to our token regardless).

## Clean areas

- `server.py` (HTTP service) — hardened: basename/`_tmp_path` containment against
  path traversal, input size caps, binary-as-text guard, loopback-only default
  bind, optional bearer auth.
- `container_meta.py` (DOCX/ODT zip handling) — has an explicit zip-bomb budget
  guard (`_check_zip_budget`), reads members as bytes (no XML entity parsing),
  no `extractall` → no zip-slip.
- trufflehog: 0 verified secrets across filesystem and full git history.
