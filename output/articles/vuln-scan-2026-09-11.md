## Agentic review (A3.6)

**Threat model:** local/self-hosted LLM inference engine. The two things an attacker most wants: (1) a crash/OOB write while the engine parses an untrusted model file (memory corruption in C), or (2) a way to read data the caller shouldn't have access to via the HTTP gateway that wraps it.

**Deep-reviewed** (of an estimated N=10 budget for this repo's 438 code files):

- `c/st.h` (safetensors shard indexer/reader — the primary untrusted-file-parsing surface). Extensively hardened already: explicit bounds checks on header length, data offsets, tensor shape/`numel` vs. byte-span cross-checks, integer-overflow guards, and inline comments naming the exact attack each guard blocks ("hostile or corrupt file"). No exploitable gap found.
- `c/json.h` (hand-rolled JSON parser used for safetensors headers and config). Already carries a fix for a prior OOB-read bug (referenced inline as `GHSA-2qrj`) on the object-key parsing path. Recursion depth is capped (`J_MAX_DEPTH`). No new issue found.
- `c/openai_server.py` (OpenAI-compatible HTTP gateway — `do_GET`/`do_POST`, auth, static file serving, image handling). Auth uses `hmac.compare_digest` (timing-safe); a Host-header check guards against DNS rebinding; `serve_static()` confines paths correctly via `resolve()` + `relative_to()`; remote `image_url` fetches are explicitly refused (no SSRF). **One confirmed finding here — see below.**

**Not deep-reviewed** (noted for honesty, not silently dropped): CUDA/Metal/Vulkan GPU backends (`backend_cuda.cu`, `backend_metal.mm`, `backend_vulkan.c`), `cli_args.h`, the C engine's internal stdin/stdout wire protocol parser in `glm53.c` (spot-checked only, not attacker-reachable directly — it's inter-process, downstream of the already-validated HTTP layer), and the `download_fp8.py`/`doctor.py`/`autotune.py`/`cluster.py` tooling scripts.

## Confirmed finding

**HIGH — CWE-22 (Path Traversal / arbitrary local file read) — `c/openai_server.py`, `_image_bytes_from_url()`**

A `/v1/chat/completions` (or `/v1/completions`, `/v1/messages`) request with a vision content part:

```json
{"type": "image_url", "image_url": {"url": "/etc/passwd"}}
```

is opened and read verbatim by the server — no `file://` prefix is even required. The only guard applied when `COLI_IMAGE_ROOT` is unset (the out-of-the-box default) is a check for a literal `..` path component, which does not restrict absolute paths at all. The function's own docstring names `file:///etc/passwd` as the exact attack it means to prevent, but that attack still works with default configuration.

This is a **follow-on to an incomplete fix**: PR #1354 ("Security: confine image_url local reads...", merged 2026-09-07, commit `9e8eb14a` — already present in the audited HEAD) added exactly the `..`-rejection and opt-in `COLI_IMAGE_ROOT` confinement described above, narrowing relative-path traversal but leaving the absolute-path case — the one the comment explicitly cites — open.

**PoC verification (A4.5):** ran `scripts/vuln-poc-gate.sh command` against a deterministic local verifier that imports the unmodified `openai_server` module, clears `COLI_IMAGE_ROOT`, writes a fixture file to a directory outside any image root, and calls the real `_image_bytes_from_url()` with that file's absolute path exactly as a client would supply it. Result: `verdict: "verified"`, `target_commit` matched the audited HEAD, `finding_sha256` bound to the claim file — the function returned the fixture's bytes byte-for-byte.

**Impact:** on a server bound beyond loopback (which already requires an API key), an *authenticated inference client* — a different trust level than the operator — can read any file the server process can open: SSH keys, `.env` files, other users' data, container-mounted secrets. Even on the documented loopback-only default, any local process/user can trigger the same read.

**Disclosed:** filed via GitHub Private Vulnerability Reporting — [GHSA-p8g4-257m-g7pm](https://github.com/JustVugg/colibri/security/advisories/GHSA-p8g4-257m-g7pm), HTTP 201, state `triage`. Full technical detail, suggested fix, and the reproduction steps are in the advisory; not reproduced here per the no-public-exploit-detail rule for PVR-routed findings.
