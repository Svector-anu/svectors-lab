## Code audit — 32 semgrep candidates, 0 confirmed in-scope

Reviewed every ERROR/WARNING plus manual review of the crown-jewel untrusted-input
surfaces. All either by-design or defended:

- **`subprocess(shell=True)`** — `mcp-scan/.../execute/execute_actions.py:46` — this is a
  registered *red-team tool* (`execute_shell`) the LLM agent invokes on purpose. Operator-
  controlled by design; not a flaw.
- **`eval`** — `mcp-scan/testcase/case1/main1.py:162` — test-case fixture, not production.
- **Go `json.Unmarshal` to `interface{}`** — `knowledge2_api.go:349` — reads a local,
  operator-controlled `strategy_map.json`; not gob, no gadget surface.
- **Archive extraction (zip / tgz)** — `common/utils/utils.go` `ExtractZipFile` /
  `ExtractTGZ` — both carry correct **zip-slip guards** (`strings.HasPrefix(cleaned, dest+sep)`),
  and tar symlink entries fall through to a no-op default case. No path escape.
- **File upload / chunked upload** — `common/websocket/task.go` `HandleUploadFile{,Chunk}` —
  `fileID` and `filename` are rejected on `..`, `/`, `\`; `validateFileUpload` checks
  name/ext/content; download path re-checks `HasPrefix(UploadDir)`. No traversal.
- **Per-user agent-config paths** — `knowledge_api.go` `safeJoinPath` + `validateUsername`
  (`isValidName` blocks `..` and non-`[a-zA-Z0-9._ -]`) — defense-in-depth prefix check
  after `filepath.Clean`. No escape (and "username" is moot under the single-operator model).
- **WebSocket agent upgrade with no `CheckOrigin`** — `common/websocket/agent.go:168` —
  CSWSH class, but the endpoint is the loopback single-operator agent channel the SECURITY.md
  scopes out. Marginal; not filed.
- **`missing-ssl-minversion` (3×), md5, `math/rand`, decompression-bomb** — either non-security
  (fingerprint hashing uses md5 as a non-cryptographic digest) or gated on operator input.
- **GitHub Actions mutable-tag (12×) / `run-shell-injection` (3×) in workflows** — CI hardening,
  operator-side, not a product vulnerability.

The codebase shows consistent, deliberate defensive engineering (zip-slip guards, path
validators, DNS-rebinding-aware HTTP handling in `pkg/httpx`). Nothing in-scope survived triage.

## Dependency finding — real, public, reachable — NOT filed (documented for operator)

**`golang.org/x/net` v0.40.0 (direct dep) — multiple `x/net/html` DoS advisories, reachable
from untrusted scan-target HTML.**

- **Reachability (confirmed):** `common/utils/favicon.go:35` feeds raw scan-target response
  bytes into `goquery.NewDocumentFromReader(...)` → `golang.org/x/net/html.Parse`; `pkg/httpx/title.go`
  imports `x/net/html` directly. Favicon-hash + title extraction run during normal fingerprinting
  of every HTTP target — i.e. against hosts AIG is pointed at precisely *because* they're untrusted.
- **Advisories affecting v0.40.0 (html parser):**
  - GO-2026-4441 — infinite parsing loop in `x/net/html` (fixed 0.45.0)
  - GO-2026-4440 — quadratic parsing complexity in `x/net/html` (fixed 0.45.0)
  - GHSA-5cv4-jp36-h3mw / GO-2026-5028 — HTML-parser DoS, CVSS AV:N/AC:L/A:H (fixed 0.55.0)
  - GO-2026-5025/5027/5029/5030 — foreign-content / DOCTYPE / duplicate-attr handling (fixed 0.55.0)
- **Also:** `golang.org/x/text` v0.25.0 → GO-2026-5970 infinite loop in `x/text/unicode/norm` (fixed 0.39.0).

**Why not filed as a public PR (the skill's channel for public dep CVEs):**
1. **Forced Go-version bump.** Every patched `x/net` (≥ v0.45.0 requires `go 1.24.0`;
   ≥ v0.52.0 requires `go 1.25.0`) lifts the module's minimum Go above its current `go 1.23.2`
   and cascades `x/crypto` / `x/sys` / `x/term` / `x/text`. That's a maintainer decision, not a
   mechanical lockfile bump.
2. **Unverifiable without the toolchain.** `go` is not in this run's allowlist, so `go mod tidy`
   / `go build` can't run. A hand-authored `go.sum` that misses one MVS-selected module would
   break their build — net-negative to a security team's repo. Do-no-harm > filing.
3. **Maintainer pre-scoped it out.** AIG's SECURITY.md lists "DoS claims that require ...
   crafted scan targets" among commonly-closed-no-change reports.

**Recommended remediation for the operator (who has a toolchain):**
`go get golang.org/x/net@latest golang.org/x/text@latest && go mod tidy && go build ./...`,
then open the dependency-bump PR from a verified build. All other OSV hits on the go.sum
(`x/crypto`, `pgx`, `circl`, `archiver`, `utls`, `fasthttp`, …) are `// indirect` / transitive
and not independently reachable — the same `go mod tidy` sweeps them.
