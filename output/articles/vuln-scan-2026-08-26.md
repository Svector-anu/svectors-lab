1. **idna 3.9.0 (PyPI)**  
   - **Location**: `optional-skills/finance/dcf-model/requirements.txt`  
   - **Advisories**: CVE-2026-45409 / GHSA-65pc-fj4g-8rjx (denial-of-service via expensive `idna.encode` on unbounded input)  
   - **Severity**: moderate (CVSS 3.1 base score 6.9)  
   - **Recommended action**: bump `idna` to **>= 3.15** and enforce a strict maximum domain length before calling `idna.encode`.

2. **electron 40.10.2 (npm, dev dependency)**  
   - **Location**: `package-lock.json`  
   - **Advisories**: CVE-2026-70608 / GHSA-9f4c-93c8-jc8g (sandboxed iframe can bypass `allow-popups` restriction via OpenURL path) and CVE-2026-70606 / GHSA-r4w5-6pfg-jxp5 (protocol handler cache isolation issue)  
   - **Severity**: high (GHSA-9f4c-93c8-jc8g), moderate (GHSA-r4w5-6pfg-jxp5)  
   - **Recommended action**: upgrade `electron` to a non-vulnerable release stream (at least **39.8.10**, **40.10.6**, **41.10.3**, or **42.0.1**, depending on which major line you follow) and, if you embed untrusted content, ensure `setWindowOpenHandler` denies unexpected windows.

3. **extract-zip 2.0.1 (npm, dev dependency)**  
   - **Location**: `package-lock.json`  
   - **Advisory**: CVE-2026-56876 / GHSA-jmr9-qjv8-65gv (unvalidated symlink path traversal when extracting archives)  
   - **Severity**: high  
   - **Recommended action**: upgrade `extract-zip` to a fixed release (latest stable recommended) and avoid extracting attacker-controlled archives without additional path validation and sandboxing.

4. **nanoid 3.3.17 (npm)**  
   - **Locations**: `package-lock.json`, `website/package-lock.json`  
   - **Advisory**: CVE-2026-67213 / GHSA-2v37-7h3g-55p8 (infinite loop in custom generators when size is zero, leading to CPU exhaustion)  
   - **Severity**: high  
   - **Recommended action**: upgrade `nanoid` to **>= 3.3.18** (or >= 5.1.6 on the newer major) and validate or bound any attacker-controlled `size` inputs passed into custom ID generators.

5. **h2 4.3.0 (PyPI)**  
   - **Location**: `uv.lock`  
   - **Advisory**: CVE-2026-71554 / GHSA-6hr6-w5qg-qmwg (duplicate `Host` header handling can facilitate HTTP request smuggling when downgrading to HTTP/1.1)  
   - **Severity**: moderate  
   - **Recommended action**: upgrade `h2` to **>= 4.4.1** and ensure any HTTP/2 → HTTP/1.1 downgrade logic enforces a single canonical `Host` header before forwarding requests.
