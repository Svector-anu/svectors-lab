## Dependencies — osv-scanner, 253 rows / 108 HIGH-CRITICAL, all deferred

The root `pnpm-lock.yaml` is a single flat graph for the *entire* pnpm workspace — every published package, every example app, every dev/build tool, and every new `harness-*` bridge package share one lockfile. That makes a raw osv-scanner count misleading for a repo this size, so before filing anything I checked reachability:

- The actually-published packages (`ai`, `@ai-sdk/provider-utils`, `@ai-sdk/provider`, `@ai-sdk/gateway`) carry a tiny runtime dependency surface: workspace-internal packages plus `zod` (peer), `undici@^7.29.0`, `json-schema`, `@vercel/oidc`, `eventsource-parser`. **None of the 108 HIGH/CRITICAL flagged package/version pairs matched this surface** (e.g. the flagged `undici@5.29.0` is a stale transitive pin elsewhere in the tree — provider-utils itself already depends on the patched `^7.29.0` line).
- Every flagged HIGH/CRITICAL traces to devDependencies, example apps (`examples/next-fastapi`'s Python deps, image/Angular example apps), or 2–4-level-deep transitive dependencies of e2e/build tooling (`plist → xmldom`, the Playwright chain, vite/esbuild/vitest).
- `gh pr list` confirms an **active Dependabot** already has 20+ open `chore(deps)` PRs covering the major direct-manifest offenders: `next`, `sharp`, `hono`, `undici`, `@angular/core`, `fastify`, `vitest`, `esbuild`, `vite`. These are duplicate-skipped rather than filing a competing PR.
- The remainder (`@xmldom/xmldom`, `multer`, `ip-address`, `websocket-driver`, `image-size`, `immutable`, `extract-zip`, `form-data`, `smol-toml`, `svgo`, `uuid`, `nanoid`, `js-yaml`, `brace-expansion`, `tar`, `tmp`, `browserslist`, `pacote`, `picomatch`, `piscina`, `postcss`, `sigstore`, `valibot`, `find-my-way`, `http-proxy-middleware`, `@opentelemetry/propagator-jaeger`, plus the Python `click`/`h11`/`starlette`/`python-multipart`/`jinja2` findings in the FastAPI example) have no open Dependabot PR, but every one checked is a transitive dependency several levels deep in dev/build/example tooling, not reachable from a published package. Filing 20+ one-off PRs against a monorepo's internal lockfile — most of them requiring a `pnpm overrides` entry rather than a simple manifest bump — is more likely to create noise/merge risk than help; deferred to the repo's own active Dependabot cadence, consistent with how this skill has handled similarly-sized monorepos (Shopify/cli, parse-server, honojs/hono — see `memory/vuln-scanned.json`).

**Channel: duplicate-skipped / deferred-to-dependabot.** No dependency PR filed this run.

## Agentic logic review (A3.6) — 0 candidates promoted

Budget: N=6 (large repo, 6,686 code files). Threat model for an LLM-facing SDK: the top attacker interest is RCE/sandbox-escape via the newer `code-mode` and `sandbox-*`/`harness-*` packages, SSRF via provider response-URL fetches, and untrusted-server surface via the MCP client — so the review targeted those over generic route-handler sweeps (this is a library, not a hosted service).

1. **`getFromApi`/`validateUrl` SSRF guard** — the repo's own `AGENTS.md` and `contributing/secure-url-handling.md` flag this as a known-sensitive control (enforced partially by an oxlint rule that only checks *presence*, not correctness, of `validateUrl`). Hand-checked all ~25 call sites across `black-forest-labs`, `fireworks`, `xai`, `fal`, `replicate`, `bytedance`, `alibaba`, `google`, `anthropic`, `revai`, `gateway`, and `openai`: every response-derived URL (image/video/audio download, polling URL, `results_url`, batch results) correctly sets `validateUrl: true` with `trustedOrigin`/`credentialedOrigin`; every baseURL-derived path (status-by-ID, file-content-by-ID, batch listing) correctly sets `validateUrl: false` with the untrusted ID safely path-encoded (`encodePathSegment`) or query-encoded (`URLSearchParams`). `google-files.ts` goes further, regex-validating and re-encoding the response-derived `file.name` before concatenation. **0 SSRF findings — this specific, documented control holds up under direct inspection.**
2. **`packages/code-mode`** (QuickJS-sandboxed tool-calling via the external `run` package) — signed/HMAC continuation tokens bound to the source and tool set, per-call timeout/memory/stack/source/tool-I/O size limits, a strict JSON-only host↔sandbox boundary (`structuredClone` + JSON round-trip, no prototype-pollution path), and an explicit approval-interrupt gate that throws before a denied tool call can execute. Sound.
3. **`packages/mcp` stdio transport** (`create-child-process.ts`) — uses `cross-spawn` with `shell: false` and array `argv`; `command`/`args` are the developer's own MCP server configuration, not remote/untrusted input. Safe.
4. **`packages/sandbox-just-bash`** — an explicitly documented in-process *virtual* bash (no real OS shell, no network namespace, no `getPortEndpoint`); env vars are exported via positional arguments rather than string-interpolated into the script. Safe by design, and the code is honest about what it doesn't do (`setNetworkPolicy` is intentionally omitted with a comment explaining why).
5. **`packages/harness-claude-code` `apiKeyHelper`** — shells out to a command read from the local user's own `~/.claude/settings.json`, mirroring the official Claude Code CLI's own supported mechanism. Same local-user trust level as the CLI it mirrors; not remotely triggerable. Dropped.

No candidate reached the PoC-verification gate (A4.5) this run because nothing survived initial triage as attacker-reachable.
