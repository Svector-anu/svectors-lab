## Threat model (brief)

OpenMAIC is a self-hostable multi-agent interactive classroom: uploads (PDF/media), LLM-backed generation, media proxying, optional Postgres persistence, and an agent workbench. Attacker goals against a networked deployment: SSRF into cloud metadata/internal services via proxy/PDF base URLs, authz bypass across learner partitions, stored XSS in shared classroom content, and RCE via unsafe document tooling. Trust boundaries: optional shared `ACCESS_CODE` cookie gate; anonymous UUID cookie for agent-session ownership; documented **development-only** persistence authenticator when `DATABASE_URL` is set.

## Entrypoints deep-reviewed (top N=6)

1. `app/api/proxy-media/route.ts` — SSRF surface; uses `validateUrlForSSRF` + redirect re-validation + size cap. Solid.
2. `lib/server/ssrf-guard.ts` — private-IP / metadata / IPv4-mapped / tunnel embedding checks. Residual DNS-rebinding TOCTOU noted, not confirmed.
3. `app/api/classroom-media/[classroomId]/[...path]/route.ts` — path traversal defenses (`..` reject, realpath jail). Solid.
4. `app/api/persistence/[...path]/route.ts` + `lib/persistence/server-auth.ts` — explicit dev-only shared-token auth; not filed as a novel flaw.
5. `middleware.ts` + `app/api/access-code/verify/route.ts` — HMAC access cookie; timing-safe compare. Solid when `ACCESS_CODE` set.
6. `app/api/web-search/route.ts` / `app/api/parse-pdf/route.ts` — client baseUrl ignored for managed providers; SSRF check on client PDF baseUrl in production.

Not deep-reviewed (noted): remaining ~60 API routes (agent sessions, materials, export-video, generate/*, pbl/*, chat/*) — owner binding on agent sessions looks correct (`meta.ownerId !== ownerId` → 404).
