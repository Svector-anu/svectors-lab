## Threat model (brief)

Attacker wants pooled-liquidity theft / flash-accounting bypass, ERC6909 claim theft, hook/lock bypass, protocol-fee theft, or CI compromise of the npm publish path. Trust boundary: anyone may `unlock` and act inside the callback; deltas must net to zero; hooks are pool-creator-chosen; owner / `protocolFeeController` are privileged.

## Entrypoints reviewed (agentic)

Deep-reviewed (top exposure):

1. `PoolManager.unlock` — lock + nonzero-delta settlement gate  
2. `PoolManager.settle` / `settleFor` / `_settle` — sync/reserves / native path  
3. `PoolManager.take` / `clear` / `mint` / `burn` — delta ↔ token ↔ ERC6909  
4. `PoolManager.swap` / `_swap` — fee accrual + hook delta accounting  
5. `PoolManager.modifyLiquidity` — position ownership = `msg.sender`  
6. `PoolManager.donate` — feeGrowth inflation (documented)  
7. `PoolManager.initialize` / `updateDynamicLPFee` — hook validation + auth  
8. `Hooks.*` — flag gates, return-delta bounds, `noSelfCall`  
9. `Pool.swap` / `modifyLiquidity` — tick/liquidity/fee math  
10. `ProtocolFees.collectProtocolFees` / `setProtocolFee` — controller-gated  
11. `ERC6909` / `ERC6909Claims._burnFrom` — allowance/operator  
12. `Currency.transfer` — ETH/ERC20 safe transfer  
13. `Extsload` / `Exttload` — intentional public state reads  
14. `.github/workflows/deploy.yaml` — release / npm publish  
15. Remaining workflows — SHA pins + Bullfrog  

Noted but not deep-reviewed beyond skim: math helpers (`TickMath`, `SqrtPriceMath`, `SwapMath`, `BitMath`, `FullMath`) — covered by prior audits + slither triage as intentional patterns; `src/test/*` helpers excluded as non-production.
