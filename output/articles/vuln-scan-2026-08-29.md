## Repo metadata

GitNexus is a client-side / local-first code-intelligence engine for AI agents: indexes a repo into a LadybugDB knowledge graph and exposes it via MCP (stdio + HTTP), CLI, and a thin React web UI over `gitnexus serve`. Attack surface concentrates on the HTTP API (`gitnexus/src/server/`), git-clone SSRF controls, multipart upload ingest, MCP auth, and the Render reverse-proxy (`docker-server.mjs`).

## Threat model (frame)

Attacker goals against a reachable GitNexus deploy: (1) read every indexed repo's source without a token, (2) SSRF into cloud metadata / RFC1918 via clone or embeddings fetch, (3) path traversal out of an indexed tree, (4) mutate/delete indexes. Trust boundaries: loopback-default `serve`, optional `GITNEXUS_PUBLIC_ORIGIN` + edge Bearer on Render, MCP stdio (local agent) vs MCP HTTP.

## Agentic entrypoints (top N=6 deep-reviewed)

1. **`server/middleware.ts` + `cli/serve.ts`** — write-origin guard; `isServeAuthConfigured()` always false. Default bind localhost; `PUBLIC_ORIGIN` refused without auth. Documented in SECURITY.md — not a new finding.
2. **`server/mcp-http.ts` → `createStreamableHttpHandler` without `authToken`** — SECURITY.md already flags this pre-existing MCP HTTP gap; Render closes it at the edge token.
3. **`server/api.ts` `handleFileRequest` / `GET /api/file`** — `assertString` + inline `path.relative` containment at the `readFile` sink. Semgrep path-traversal WARNING is a false positive.
4. **`server/git-clone.ts` `validateGitUrl`** — extensive literal IP / IPv6 / NAT64 / 6to4 blocking (prior #1148). No DNS-resolve-then-check; DNS-rebinding remains a hardening gap, but default loopback bind + SECURITY.md "default deployment" scope means it is not filed as a confirmed finding.
5. **`server/upload-ingest.ts`** — segment/`..` rejection, sandbox prefix check, symlink-resistant `mkdirContained`. Solid.
6. **`mcp/local/local-backend.ts` `cypher`** — LadybugDB opened read-only; write ops return a curated error. Safe for the MCP tool surface.

Also reviewed (not deep): SSE progress JSON frames (semgrep XSS FP — `text/event-stream` + `JSON.stringify`), SPA `sendFile(index.html)` constant path, embeddings HTTP client (operator-configured base URL).
