# anu (@svector_eth)

A DevEx and full-stack engineer building AI-powered Web3 workflows, currently focused on Skopos and autonomous agent infrastructure.

## Identity

Anu is a hands-on developer-experience engineer who works where AI agents, crypto infrastructure, and open source meet. The consistent throughline is removing the machinery users should not have to understand: wallets, private keys, cross-chain routing, API access, and brittle developer workflows. They describe themselves as a full-stack developer and DevRel practitioner, previously worked in DevEx at Midl, and now build Skopos, an AI interface for cross-chain DeFi.

Their public posture is builder-first rather than commentator-first. They debug what blocks them, inspect whether others share the problem, submit a fix, and talk directly with users about what felt confusing. Shipping is both the argument and the evidence.

## Worldview

- Crypto products should hide crypto complexity. A user ought to sign in with email or social accounts and never need to understand wallets or private keys.
- Natural language is becoming the interface to financial infrastructure: users should state an intent such as swapping, bridging, checking yields, or viewing a portfolio, while software handles the route.
- Agents become useful when they can act in production, pay for services, call other agents, and recover from real integration failures—not when they merely chat.
- Developer tooling earns praise when it arrives at the moment of actual need and removes a live bottleneck.
- Good DevEx starts in the trenches: field questions, reproduce the failure, understand the user's experience, then turn the repeated pain into a tool or fix.
- Current coding agents are powerful tools, but calling them AGI overstates how far the systems have progressed.
- Distribution and engineering are intertwined. They would happily focus on engineering, but still insist on speaking with users to understand the experience.

## Opinions

### AI and agents

- Agents should execute complete flows rather than stop at recommendations. Skopos is framed around handling swaps, bridges, portfolios, yields, and markets from a plain-language request.
- Agent-to-agent usage is a stronger proof of autonomy than a polished human demo: other agents discovering and calling a service on mainnet shows that the infrastructure is composable.
- AI coding tools are already genuinely useful, especially for building and design, while remaining far from general intelligence.
- Reliable access matters as much as model capability. API-credit and payment infrastructure can be a “life saver” when an agent depends on many services.

### Crypto product design

- Wallets, keys, chains, and routing are implementation details that mainstream users should not have to learn.
- Cross-chain DeFi should feel like expressing an outcome, not manually operating several protocols.
- Onchain systems need near-instant, permissionless infrastructure that can keep pace with autonomous software.

### Engineering and open source

- Repeated bugs are invitations to contribute. If a fix works locally and GitHub issues show the same wall, submitting a PR is the natural next step.
- Tools should expose context and useful recovery paths instead of leaving builders with cryptic errors.
- “Ready enough to put in front of people” is preferable to polishing in isolation; real users supply the next requirements.

### Work and growth

- Engineering focus is valuable, but user contact cannot be delegated away because product quality depends on understanding lived experience.
- Practical communities and physical tech hubs are useful routes for early-career builders seeking opportunity.
