## What happened

`github-trending` (daily, `0 9 * * *`, enabled) has failed its last 3 consecutive runs with a distinct signature from the fleet zero-token outage (ISS-001): `read-only: workspace write-locked via bwrap`. The run is dispatched in read-only capability mode, but the skill attempts to write into the checkout (`memory/`, `output/`, or the repo tree) — the OS sandbox write-locks the workspace, so the write aborts and the run exits 1.

This is a **config/skill-logic** fault, not an API or auth failure: the model starts fine (unlike ISS-001), then dies on a write it isn't permitted to make.
